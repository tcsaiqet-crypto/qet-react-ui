## 3. Subagent 6a — Executive Summary Writer

### What It Does
Reads complete execution results, test suite scope, and BR coverage. Writes a professional 3-paragraph narrative for CFA Institute QA leadership.

### File: Update `backend/src/agents/report_agent.py`
```python
def _generate_executive_summary(self, state: AppState, stats: dict) -> str:
    chain = self.router.get_chain("exec_summary", EXEC_SUMMARY_PROMPT, ExecSummaryOutput)
    result = chain.invoke({
        "total_cases": stats["total"],
        "passed": stats["passed"],
        "failed": stats["failed"],
        "pass_rate": stats["pass_rate"],
        "br_coverage": self._build_br_coverage_map(state),
        "failure_summaries": self._collect_failure_summaries(state),
        "run_date": datetime.now(timezone.utc).strftime("%Y-%m-%d"),
        "platform": "CFA Digital Candidate Journey",
    })
    return result.summary_text
```

### Prompt
```
You are writing for CFA Institute QA leadership. Be professional, precise, and concise.

Context:
- Platform: CFA Digital Candidate Journey
- Run Date: {run_date}
- Total Test Cases: {total_cases}
- Passed: {passed} | Failed: {failed} | Pass Rate: {pass_rate}%
- BR Coverage: {br_coverage_json}
- Failure Summaries: {failure_summaries_json}

Write exactly 3 paragraphs (max 250 words total):
Paragraph 1: What was tested — scope of BR coverage and test types
Paragraph 2: Key findings — results with business impact framing (not technical)
Paragraph 3: Overall risk posture and recommended position for the next exam window
```

### Example Output

```
Overall business risk is assessed as Medium. The KYC and Booking failures are non-blocking for

or score integrity.

Generated by Gemini Pro | 2026-08-17 07:30 UTC
```

## 4. Subagent 6b — Root Cause Analyst

### What It Does
Groups failure cases by shared characteristics and identifies systemic root causes.

### Clustering Logic (AI-driven)
```python
def _generate_root_cause_report(self, failures: List[dict]) -> str:
    chain = self.router.get_chain("root_cause", ROOT_CAUSE_PROMPT, RootCauseOutput)
    result = chain.invoke({"failures": failures})
    return result.analysis_text
```

### Prompt
```
Analyze these {count} Playwright test failures and identify systemic root causes.

Failures: {failures_json}

Look for patterns:
- Shared selector failures across multiple cases (locator regression)
- Shared BR failures (one requirement has multiple failing cases)
- Shared page route failures (one flow stage is broken)
- Shared failure classification (all timing_issue or all application_defect)

Return a RootCauseOutput with:
- analysis_text: 2–3 paragraph plain-English root cause analysis
- primary_theme: the single biggest cluster ("selector regression", "BR-02 KYC flow", etc.)
- affected_case_ids: list of case IDs in the primary cluster
- secondary_themes: list of other identified themes
```

### Example Output
```
Root Cause Analysis — Primary Theme: Shared Selector Regression in KYC Flow

Two of four failures share a common selector defect on the `#kyc-upload-trigger` element across 
TC-NEG-001 and TC-VAL-002. This indicates a recent UI component update to the KYC document 
upload module changed the button's data-testid attribute without updating the automated test suite.

A secondary theme involves a timing issue on TC-BND-001 (Exam Booking) where the session 
availability API response takes longer than the default 30-second timeout under load, causing 
a false failure. This is likely environment-specific and should be validated on staging.

No application logic defects were detected. All failures have clear, addressable remediation paths.
```

## 5. Subagent 6c — BR Risk Heatmap Generator

### What It Does
For all 18 BRs, produces a structured risk table based on test results.

### Risk Calculation Logic
```
BR Risk Level = f(test_cases_failed, test_cases_passed, BR_criticality)

HIGH if:   any critical test case for this BR failed
MEDIUM if: any non-critical case failed OR coverage < 100%
LOW if:    all test cases passed AND full coverage
NONE if:   no test cases mapped to this BR (coverage gap)
```

### Prompt
```
Compute a business risk score for each CFA requirement based on test execution results.

Requirements: {requirements_json}
Final Test Suite with Results: {test_suite_with_results_json}
Failure Classifications: {failure_classifications_json}

Return a list of BRRiskEntry objects, one per requirement, with:
- requirement_id, risk_level (Low/Medium/High/Critical), 
- test_cases_passed, test_cases_failed, coverage_percentage
```

### HTML Report Table
