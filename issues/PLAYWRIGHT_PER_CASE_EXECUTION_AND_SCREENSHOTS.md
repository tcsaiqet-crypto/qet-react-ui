# Playwright Per-Case Execution, Screenshot Evidence & Interactive Runner

## 1. Core Execution Architecture

Every test case generated by QET maps 1-to-1 to a self-contained, executable Python Playwright test script.

```
workspace/generated_playwright_tests/
├── pages/
│   ├── base_page.py
│   └── cfa_portal_page.py
├── tests/
│   ├── test_TC_POS_001_valid_login.py
│   ├── test_TC_NEG_002_invalid_password.py
│   ├── test_TC_BND_003_income_boundary.py
│   ├── test_TC_VAL_004_ssn_formatting.py
│   └── test_TC_ERR_005_network_timeout.py
└── artifacts/
    └── screenshots/
        ├── TC_POS_001_PASSED.png
        ├── TC_NEG_002_PASSED.png
        └── TC_ERR_005_FAILED.png
```

## 2. Automated Screenshot Capture Strategy

Screenshots are captured in both success and failure scenarios via try/finally blocks:

```python
# Template injected into each test script:
try:
    # 1. Arrange & Act
    login_page.navigate()
    login_page.login(username=data["username"], password=data["password"])
    
    # 2. Assert
    expect(page.locator("#dashboard-welcome")).to_be_visible()
    
    # 3. Capture Success Screenshot
    page.screenshot(path=f"artifacts/screenshots/{test_case_id}_PASSED.png", full_page=True)
except Exception as e:
    # 4. Capture Failure Screenshot on Error
    page.screenshot(path=f"artifacts/screenshots/{test_case_id}_FAILED.png", full_page=True)
    raise e
```

## 3. Interactive UI Selection & Execution Controls

The `LivePlaywrightRunner` UI provides dynamic selection and sequential or batch execution:

```
┌─ Test Case Selection & Execution ──────────────────────────────────────────────┐
│  [☑ Select All (12)]   [☐ Clear Selection]   [Filters: Positive | Negative...]  │
│                                                                                │
│  ☑ TC-POS-001  Valid User Authentication     [View Script] [View Data] [Ready] │
│  ☑ TC-NEG-002  Invalid Password Rejection    [View Script] [View Data] [Ready] │
│  ☐ TC-BND-003  Minimum Income Threshold      [View Script] [View Data] [Ready] │
│                                                                                │
│  ┌──────────────────────────────────────────────────────────────────────────┐  │
│  │ 🚀 Proceed & Run Selected (2 Cases)     |   ▶ Run Sequential (One-by-One)│  │
│  └──────────────────────────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────────────────┘
```

### Key UI Features:
1. **Multi-Select Checkboxes**: Select individual test cases (e.g., test cases 1 and 2 only).
2. **Bulk Actions**:
   - `Select All`: Selects all filtered cases.
   - `Clear Selection`: Clears all selections.
   - Category filter pills (Positive, Negative, Boundary, Validation, Error Handling).
3. **Dynamic "Proceed / Run Selected" CTA**: Only active when `>= 1` test case is selected.
4. **Execution Modes**:
   - **One-by-One (Sequential)**: Focuses on one test at a time, displaying live logs and screenshot as it completes.
   - **Batch Execution**: Runs the selected suite with progress indicators.
5. **Interactive Evidence Inspection**:
   - Click test case row to view step logs.
   - Click screenshot thumbnail to open full-screen zoom preview with download option.
