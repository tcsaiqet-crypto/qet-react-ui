Current Routing

Current implementation: Gemini is the persisted default provider. The active provider is resolved from runtime AI settings, with Gemini used whenever no explicit GPT selection is stored.

Gemini key-source precedence

  1. Runtime AI settings: provider_keys.gemini
  2. GEMINI_API_KEY
  3. GOOGLE_API_KEY
  4. Supported local Gemini key files under backend, project, and API key directories

Keys are de-duplicated, placeholder values are rejected, and key material must never be stored in documentation, logs, or UI responses.

An explicit GPT selection remains supported. Understanding respects the selected provider and exposes an AI failure instead of falsely claiming a successful analysis.

Gemini Model Selection

Current implementation: QET has no fixed model assigned to an individual agent. For each Gemini key, it discovers models using Google ListModels, filters to generateContent-capable candidates, then ranks them.

  1. *-latest candidates first
  2. Flash
  3. Flash Lite
  4. Pro
  5. Other text-capable candidates

The first model that returns usable content is cached for that key during the current process. Current generation configuration is temperature 0.2 and a 2500-token maximum.

Prompt Guidance

Understanding

Current prompt requests JSON summary, architecture notes, components, flows, gaps, entry points, and testability observations from document names and source snapshot. Add evidence rules: prefer [data-testid] selectors, attach file paths, and do not invent routes, APIs, selectors, or requirements.

Requirement Categorization

Current prompt requires a closed requirement-type enum. Add examples for security, accessibility, and integration; preserve source evidence; and use an explicit uncategorized state only when evidence is insufficient.

Test Cases

Current prompt requests 10-14 JSON cases across positive, negative, boundary, validation, and error handling. Add direct requirement/gap traceability, observable expected outcomes, automation-candidate constraints, and a priority rule when output is limited.

Prompt and Model Governance

Every AI artifact should retain provider, discovered model, prompt version, timestamp, source artifact identifiers, validation status, and fallback reason. JSON output must be parsed and validated against Pydantic contracts. Invalid output should become a transparent failure, not synthetic success data.

backend/src/prompts/
  understanding_v1.py
  requirement_categorization_v1.py
  test_cases_v1.py

Prompt builders should be versioned and typed. Agent provenance should record the exact prompt version.

Implementation Plan

  1. Keep Gemini as the persisted default provider.
  2. Add per-agent capability profiles to the shared LLM service.
  3. Persist actual model and prompt version in every AI artifact.
  4. Move prompt builders into versioned modules.
  5. Add prompt-contract tests using fixture source snapshots.
  6. Measure JSON-invalid and truncation rates before changing budgets or model tiers.

The right distinction is task shape, not arbitrary key assignment: fast structured models for synthesis, lightweight models for classification, stronger fallbacks for exceptional reasoning, and no model for deterministic or safety-critical functions.
