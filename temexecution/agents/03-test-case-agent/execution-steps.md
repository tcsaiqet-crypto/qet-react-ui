# Test Case Execution Steps

1. Confirm Understanding is valid and current-generation.
2. Confirm categorization dependency according to configuration.
3. Build test cases from requirements, flows, components, and gaps.
4. Include positive, negative, boundary, validation, security, and accessibility cases where evidence supports them.
5. Link every case to a requirement or record why it is exploratory.
6. Validate IDs, steps, expected results, priority, and type.
7. Persist the suite and provenance.
8. Emit lifecycle events for start, completion, and failure.
9. Block Test Data when the suite is invalid or empty.
10. Test dependency blocking, traceability, and retry invalidation.
